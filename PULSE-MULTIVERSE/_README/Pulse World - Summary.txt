In a browser‑native OS like PulseWorld, timers, render loops, and awaits are a kind of controlled insanity
 — every millisecond is a negotiation between the event loop, the GPU compositor, the network stack, and the
  warm‑state engines. A single synchronous block doesn’t just “pause” execution; it freezes the entire dimension,
   stalls the renderer, starves the GPU, and forces the browser to halt everything until the sync task finishes.
    That’s why async isn’t optional — it’s oxygen. Async keeps the PulseBand heartbeat alive, keeps the GPU warm,
     keeps the viewport streaming, and prevents the world from collapsing into jank. In PulseWorld physics,
      sync is a brick wall; async is a river. The system must always flow, never block, never stall, never freeze
       — because a dimensional OS can only stay alive if every subsystem breathes in parallel.

       PulseOS is a non-blocking system.

No synchronous operation may stall:
- the event loop
- the renderer
- the GPU pipeline
- the network pipeline
- the PulseBand heartbeat

All execution must be asynchronous or partitioned.

Sync = blocking wall
Async = continuous flow

A subsystem that blocks is a subsystem that violates system life.
